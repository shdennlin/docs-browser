# T-0.4: Mermaid under the planned CSP

Date: 2026-11-24. Platform: macOS, Chrome (current), Mermaid 12.3.0 `mermaid.min.js`, loaded as a classic script.

**ANSWER: Mermaid needs `style-src 'unsafe-inline'`. The policy in PRD 12.5 stays as written; it cannot be tightened.**

## Method (measured)

A throwaway page loaded `mermaid.min.js`, `markdown-it.umd.min.js`, `markdown-it-task-lists.min.js` and `highlight.min.js` from `'self'` (no inline script) and rendered
`flowchart LR; Browser --> API; API --> Database` with `securityLevel: 'strict'`. It served the same page under two CSPs and counted `securitypolicyviolation` events.

| Policy | Mermaid render | SVG count | CSP violations | Node `rect` fill |
|---|---|---|---|---|
| `style-src 'self'` (strict) | rendered, degraded | 1 | 37 (`style-src-elem` 2, `style-src-attr` 35) | `rgb(0, 0, 0)` (styles blocked, black shapes) |
| `style-src 'self' 'unsafe-inline'` (PRD 12.5) | rendered, styled | 1 | 0 | `rgb(255, 255, 255)` |

Other measured facts:

- Globals present under both policies: `window.mermaid` (object), `window.markdownit` (function), `window.markdownitTaskLists` (function), `window.hljs` (object).
- `markdown-it` with the task-list plugin and `html: false` produced 2 checkboxes and 1 table from a test input.
- `script-src 'self'` was sufficient; Mermaid did not need `'unsafe-eval'` or inline scripts. No script-src violations occurred.
- With the strict policy Mermaid emits an inline `<style>` element (2 violations of `style-src-elem`) and 35 inline `style=` attributes (`style-src-attr`).

## Implications for the PRD

- 12.5: keep `style-src 'self' 'unsafe-inline'`. Add the measured reason: Mermaid injects an inline `<style>` and inline style attributes.
- Pin the Mermaid artifact: `frontend/vendor/mermaid.min.js` from `mermaid@12.3.0` `dist/mermaid.min.js` (already recorded in `VERSIONS`).
