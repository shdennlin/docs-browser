# T-0.8 Spike: macOS `canonicalize`, case and Unicode behaviour

All results below are **measured** (a throwaway std-only Rust program was run; nothing is guessed). Unmarked rows are measured. Statements that go beyond the measurements are labelled **by construction**.

## Environment

| Item | macOS | Linux |
|---|---|---|
| OS | Darwin 27.2.0 | Linux aarch64 (Docker via OrbStack, image `rust:1`) |
| rustc | 1.95.0 (59807616e 2026-04-14) | 1.100.0 (0ef1bc386 2026-11-09) |
| Volume holding fixtures | APFS, `/System/Volumes/Data` (`/dev/disk3s5`), `diskutil` personality "APFS" (not "Case-sensitive") | container-local `overlay` at `/tmp/fx` (copied with `cp -a`, no bind mount; symlinks verified as symlinks) |

Test program: `canonicalize(ROOT.join(input))`, `starts_with(ROOT)`, and an `eq_ignore_ascii_case` check of every path component against `.git node_modules dist build .cache`, applied to (a) the requested ("listed") path and (b) the returned canonical path made relative to ROOT. Scratch code and raw outputs live outside the repo in the session scratchpad (`spike-t08/spike.rs`, `mac-*.txt`, `linux-paths.txt`).

## Q1. Case sensitivity and `canonicalize` of case variants

**ANSWER: The macOS fixture volume is case-insensitive, and `canonicalize` there succeeds and returns the on-disk spelling (not the requested one), so a case-insensitive comparison on the returned canonical path alone blocks all four inputs; on Linux the case variants fail with NotFound.**

Evidence that the volume is case-insensitive: `DOCS/api.md` and `Public/config` resolve on macOS and fail on Linux (the container fs is case-sensitive; also `touch a A` created 2 files there).

| Input (joined onto canonical ROOT) | Platform | Result | Returned canonical (relative to ROOT) | blocked(listed) | blocked(canon) |
|---|---|---|---|---|---|
| `Node_Modules/pkg/index.md` | macOS | OK | `node_modules/pkg/index.md` (on-disk case) | true | true |
| `.GIT/config` | macOS | OK | `.git/config` (on-disk case) | true | true |
| `docs/UPPER.MD` | macOS | OK | `docs/UPPER.MD` | false | false |
| `DOCS/api.md` | macOS | OK | `docs/api.md` (on-disk case, `DOCS` -> `docs`) | false | false |
| `docs/upper.md` (extra) | macOS | OK | `docs/UPPER.MD` (file name case also normalized) | false | false |
| `Node_Modules/pkg/index.md` | Linux | ERR NotFound | - | - | - |
| `.GIT/config` | Linux | ERR NotFound | - | - | - |
| `docs/UPPER.MD` | Linux | OK | `docs/UPPER.MD` | false | false |
| `DOCS/api.md` | Linux | ERR NotFound | - | - | - |
| `docs/upper.md` (extra) | Linux | ERR NotFound | - | - | - |

Sufficiency of the comparison (all measured on the rows above):

- On macOS the canonical path always carried the real on-disk spelling, so `eq_ignore_ascii_case` on the returned path blocks `Node_Modules/...` and `.GIT/config`. The comparison should stay case-insensitive (PRD wording) as defence in depth; this spike did not test a volume holding a differently-cased real directory such as `Node_Modules`.
- The LISTED-path comparison is **not** needed to defeat case tricks on either platform: on macOS the canonical path has already been normalized, on Linux the variant never resolves. Case evasion is fully covered by the canonical check.
- The LISTED-path check is still needed for a different reason, shown by the symlink rows in Q2: `public` (listed, visible) resolves to `.git` (canonical, blocked). The reverse case, a listed hidden or dot-prefixed component that resolves to a visible canonical path (for example a dot-prefixed symlink to `docs`), would be caught only by the listed check. That reverse case was not part of these fixtures and is **by construction**, not measured.

## Q2. Symlink fixtures

**ANSWER: `canonicalize` fully resolves every symlink fixture identically on macOS and Linux (modulo `/etc` -> `/private/etc` on macOS); `starts_with(ROOT)` accepts `public`, `link-in/...` and `loop/self`, and rejects `link-out/hosts` and `evil/secret.md`; `public` is then caught by the canonical visibility check.**

| Input | Platform | Canonical result | starts_with(ROOT) | blocked(canon) |
|---|---|---|---|---|
| `public` (-> `.git`) | macOS | `<ROOT>/.git` | true | true |
| `public` (-> `.git`) | Linux | `<ROOT>/.git` | true | true |
| `public/config` | macOS / Linux | `<ROOT>/.git/config` | true | true |
| `link-in/architecture.md` (-> `docs`) | macOS | `<ROOT>/docs/architecture.md` | true | false |
| `link-in/architecture.md` | Linux | `<ROOT>/docs/architecture.md` | true | false |
| `link-out/hosts` (-> `/etc`) | macOS | `/private/etc/hosts` | false | n/a |
| `link-out/hosts` | Linux | `/etc/hosts` | false | n/a |
| `evil/secret.md` (-> `../site-evil`) | macOS | `<fixtures>/site-evil/secret.md` | false | n/a |
| `evil/secret.md` | Linux | `/tmp/fx/site-evil/secret.md` | false | n/a |
| `loop/self` (-> `..`) | macOS | `<ROOT>` itself | true | false (empty relative path) |
| `loop/self` | Linux | `<ROOT>` itself | true | false (empty relative path) |
| `Public/config` (extra, case variant of symlink) | macOS | `<ROOT>/.git/config` | true | true |
| `Public/config` | Linux | ERR NotFound | - | - |

Notes:

- `<ROOT>` = `<repo>/tests/fixtures/site` on macOS, `/tmp/fx/site` on Linux.
- `starts_with` rejected the sibling `site-evil` (shared name prefix) on both platforms, confirming the component-wise behaviour PRD 12.2 step 5 relies on.
- `loop/self` is not an error: `loop/self` -> `..` is just the root, so it canonicalizes to ROOT. It is not an infinite loop (the fixture is a parent link, not a cycle). A true cycle (a -> b -> a) was not part of the fixtures and was not tested.
- Because `loop/self` canonicalizes to ROOT, step 7 (must be a regular file) is what denies it, not step 5.

## Q3. Unicode normalization

**ANSWER: APFS (via `read_dir`, `open` and `canonicalize`) stores and returns the name exactly as created (the CJK fixture is byte-identical in NFC and NFD; `café.md` created as NFD is returned as NFD, created as NFC is returned as NFC), and lookups succeed with either spelling, so the volume is normalization-insensitive but normalization-preserving; `canonicalize` returns the on-disk form, not the requested form.**

CJK fixture `docs/中文 筆記.md`: `read_dir` returns bytes `e4 b8 ad e6 96 87 20 e7 ad 86 e8 a8 98 2e 6d 64`. Python confirmed that `NFC(s) == NFD(s) == s` for this string, so it cannot discriminate normalization; hence the accented-Latin test below.

| Case | read_dir bytes | Lookup spelling | open | canonicalize file name (bytes) |
|---|---|---|---|---|
| File created as NFD `café.md` | `63 61 66 65 cc 81 2e 6d 64` (NFD) | NFC `63 61 66 c3 a9 ...` | ok | NFD `63 61 66 65 cc 81 ...` |
| same file | same | NFD | ok | NFD |
| File created as NFC `café.md` | `63 61 66 c3 a9 2e 6d 64` (NFC) | NFC | ok | NFC `63 61 66 c3 a9 ...` |
| same file | same | NFD `63 61 66 65 cc 81 ...` | ok | NFC (on-disk form returned) |
| CJK `中文 筆記.md` | `e4 b8 ad ...` | NFC and NFD (identical bytes) | ok | `e4 b8 ad ...` (same) |

Consequences (measured facts only): a URL spelled in NFC reaches an NFD-stored file and vice versa; the canonical path carries the stored spelling, which may differ in bytes from the request. Comparing the request string to a `read_dir` name byte-for-byte (for example for tree-to-URL matching, or `LISTED` vs `CANON` equality) can mismatch on macOS for non-ASCII names. Linux behaviour for Unicode was not measured (not requested).

## Implications for the PRD

1. **PRD 7.1 / 12.2 step 6 (visibility on both LISTED and CANON): keep as written.** The canonical check is what stops case variants (`Node_Modules/...`, `.GIT/config`) on macOS because `canonicalize` returns the on-disk spelling (measured), and it is what stops the `public` -> `.git` symlink (measured). The listed check is not needed for case on either platform (macOS normalizes, Linux does not resolve); keep it for symlink-alias coverage and dot-prefix semantics as the PRD says. No wording change is required, but the rationale could be sharpened: "the canonical check defeats case-variant input on case-insensitive volumes; the listed check defeats alias names".
2. **PRD 12.2 closing paragraph:** replace "T-0.8 records what `canonicalize` returns" with the result: on macOS (APFS, case-insensitive) `canonicalize` succeeds for case variants and returns the on-disk spelling; on Linux it fails with NotFound. Optionally add: "Visibility comparisons on the canonical path are sufficient against case variants; they stay case-insensitive on every platform."
3. **Step 5 (`starts_with(ROOT)`) is sound on macOS** because both sides come from `canonicalize` and share the on-disk spelling; it also correctly rejects `site-evil` and `/etc` targets (measured on both platforms). Note macOS resolves `/etc` to `/private/etc`, so any test asserting the canonical string for `link-out` must be platform-aware.
4. **Add a Unicode note to 12.2:** "macOS volumes preserve the stored normalization form but match either form on lookup; `canonicalize` returns the stored form. Do not compare request strings and directory-entry names byte-wise; compare canonical paths." Any component that builds URLs from `read_dir` names (tree, search index, link resolution) should treat the stored bytes as authoritative and, if matching user-typed paths against the index, normalize both sides to one form (NFC) for the comparison only. The CJK fixture alone is not a sufficient Unicode test; if a normalization test is added to the suite it must use an accented Latin name such as `café.md` created as NFD.
5. **Test-suite impact:** UT-01 to UT-07 (T-1.1) case-variant tests must expect "OK + blocked" on macOS and "NotFound" on Linux; both outcomes are denials (404), so a single assertion "denied" is portable. `docs/UPPER.MD` and `docs/upper.md` differ: the latter resolves on macOS only.
6. **Not covered by this spike:** case-sensitive APFS volumes, a symlink cycle (a -> b -> a), and Linux Unicode behaviour. None are required by the T-0.8 acceptance criteria.
