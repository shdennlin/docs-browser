# T-0.5: `cargo package` / `cargo publish --dry-run`

Date: 2026-11-24. cargo 1.95.0.

**ANSWER: the package contains `frontend/` (all 11 vendored files). The dry run succeeds once fixtures are excluded.**

## Measured

- `cargo package --list --allow-dirty` after adding `exclude = ["/tests/fixtures", "/.claude", "/target"]` lists every file under `frontend/vendor/`. File counts grow as the repository grows: re-measured at CP-0, the stdout list (`cargo package --list`, stderr excluded) and the dry run both report the same number of files (31). The first measurement showed 22 list lines against 19 packaged files; the likely cause is that the 22 came from a command that merged stderr into the count (inferred, not re-checked).
- `cargo publish --dry-run --allow-dirty`: `Packaged 19 files, 5.6MiB (1.6MiB compressed)`; the verify build compiled; `aborting upload due to dry run`.
- crates.io's package size limit is 10 MiB compressed (read, not measured here); 1.6 MiB is well inside it.

## Pitfall found (measured)

Before the `exclude` was added, `cargo package` walked `tests/fixtures/` and followed the fixture symlink `link-out -> /etc`, then failed on `/etc/aliases.db` with `Permission denied`. The `.gitignore` entry did not help because the repository had no commits. Keep the `exclude` entry in `Cargo.toml`; without it, packaging reads files outside the project.
