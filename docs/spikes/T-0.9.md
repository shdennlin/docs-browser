# T-0.9: axum extractor decoding spike

Every claim below is **measured**: a throwaway binary was run and probed with `curl --path-as-is`. Nothing is inferred from source or docs.

## Environment

- `rustc 1.95.0 (59807616e 2026-04-14)`, edition 2021
- `axum = "=0.8.9"` (confirmed in Cargo.lock), `tokio 1` (full)
- Throwaway crate: `<scratchpad>/spike-t09/` (not part of the repo).
- Routes on 127.0.0.1:4191: `GET /files/{*path}` echoes `Path<String>` with `{:?}`; `GET /api/file` echoes `Query<HashMap<String,String>>` `path` key (`Option<&String>` with `{:?}`) and whether the key is absent. No middleware, no normalisation layer.
- Handler-saw column uses Rust `{:?}` debug escaping: `\0` is a NUL byte, `\\` is one backslash.

## Evidence table: wildcard `/files/{*path}`

| Input (sent as-is) | Status | Handler saw (`Path<String>`) |
|---|---|---|
| `/files/a/b.md` | 200 | `"a/b.md"` |
| `/files/%2e%2e/%2e%2e/etc/hosts` | 200 | `"../../etc/hosts"` |
| `/files/%252e%252e/x` | 200 | `"%2e%2e/x"` |
| `/files/..%2fx` | 200 | `"../x"` |
| `/files/a%00b` | 200 | `"a\0b"` (3 bytes, real NUL) |
| `/files/a%5Cb` | 200 | `"a\\b"` (3 bytes, real backslash) |
| `/files/%E4%B8%AD%E6%96%87%20%E7%AD%86%E8%A8%98.md` | 200 | `"中文 筆記.md"` |
| `/files/../../etc/hosts` (raw dot segments) | 200 | `"../../etc/hosts"` |
| `/files//a` | 200 | `"/a"` (leading slash kept) |
| `/files/` | 404 | route does not match (empty wildcard), handler not called |
| `/files/%zz` | 200 | `"%zz"` (literal) |
| `/files/a%2Fb` | 200 | `"a/b"` |

## Evidence table: `/api/file?path=`

| Input query | Status | Handler saw (`path`) |
|---|---|---|
| `?path=docs/a.md` | 200 | `Some("docs/a.md")` |
| `?path=%2e%2e%2f%2e%2e%2fetc%2fhosts` | 200 | `Some("../../etc/hosts")` |
| `?path=%252e%252e` | 200 | `Some("%2e%2e")` |
| `?path=a%00b` | 200 | `Some("a\0b")` |
| `?path=docs%5C..%5Cx` | 200 | `Some("docs\\..\\x")` |
| `?path=%E4%B8%AD%E6%96%87%20x.md` | 200 | `Some("中文 x.md")` |
| `?path=` | 200 | `Some("")` (present, empty) |
| no query | 200 | `None`, absent = true |
| `?path=a&path=b` | 200 | `Some("b")` (last duplicate wins) |
| `?path=%zz` | 200 | `Some("%zz")` (literal) |

## Q1. Does axum decode exactly once for both Path and Query?

ANSWER: Yes (measured). `%252e%252e` arrives as the literal `%2e%2e` on both extractors and is never turned into `..`.

Evidence: `/files/%252e%252e/x` gave `"%2e%2e/x"`; `?path=%252e%252e` gave `Some("%2e%2e")`. Single-decoded `%2e%2e` gave `..` on both (`../../etc/hosts` rows), so one decode pass happens and only one.

## Q2. Is an encoded slash decoded to `/` in a wildcard capture, and does `%2e%2e` become `..`?

ANSWER: Yes to both (measured). `%2f` becomes `/` and `%2e%2e` becomes `..` inside the capture.

Evidence: `/files/a%2Fb` gave `"a/b"`; `/files/..%2fx` gave `"../x"`; `/files/%2e%2e/%2e%2e/etc/hosts` gave `"../../etc/hosts"` with status 200. The router does not reject these. The resolver therefore WILL see `..` components from encoded input and must reject them itself (PRD step 3).

## Q3. NUL (`%00`), backslash (`%5C`), invalid encoding (`%zz`)

ANSWER: None are rejected by axum; all are delivered to the handler with status 200 (measured).

Evidence: `a%00b` arrives as a string containing a real NUL byte on both extractors; `a%5Cb` as a real backslash on both; `%zz` as the literal three characters `%zz` on both (invalid percent-encoding is passed through, not a 400). Separately, `/files//a` arrives as `"/a"` (leading `/`, which `Path::components()` reports as `RootDir`, and `join` would replace ROOT), and `/files/` does not match the route at all (404, empty wildcard). A missing `path` query key is distinguishable from an empty value (`None` vs `Some("")`). Duplicate keys with a `HashMap` keep the last value.

## Q4. Do raw `..` segments sent with `--path-as-is` reach the handler un-normalised?

ANSWER: Yes (measured). Neither the server nor the router normalises or rejects them.

Evidence: `curl --path-as-is /files/../../etc/hosts` gave status 200 and `"../../etc/hosts"` in the handler, identical to the percent-encoded form. Caveat: this only shows the server side; browsers and many HTTP clients normalise dot segments before sending, but an attacker with curl does not have to.

## Q5. Is 'the resolver never decodes; it receives the single-decoded string' sound?

ANSWER: Yes (measured), with the condition that the resolver is fed only by `Path<String>` / `Query<..>` and never re-decodes. Both extractors decode exactly once (Q1) and give the same strings for the same logical input.

Evidence: all paired rows are identical across extractors (`../../etc/hosts`, `%2e%2e`, `a\0b`, backslash, CJK plus space, `%zz`). A double-encoded payload stays an inert literal file name, as PRD 12.2 step 2 states. Not measured here: `+` handling in queries, non-UTF-8 percent-sequences (e.g. `%FF`), and the PRD's deep-link `?file=` (that is a client-side param, not a server extractor).

## Implications for the PRD

- **12.2 step 2 (no decoding in resolver): no change needed.** Confirmed by Q1 and Q5.
- **12.2 step 3 (reject NUL, backslash, ParentDir/RootDir/Prefix): no change needed, and it is load-bearing.** Q2 and Q3 show NUL, backslash and `..` all reach the resolver with status 200, so the resolver is the only defence. The `/files//a` case yields a leading `/` that must hit the `RootDir` rejection; a test for it is recommended (suggested addition to AC-20, not a PRD change).
- Recommended clarification (wording only): note that `/api/file` with no `path` key and with `path=` both must return 404 (`None` vs `Some("")`, handlers must handle both; AC-35 already covers the missing case), and that duplicate `path` keys resolve to the last value with `HashMap`.
- Optional hardening: if the project wants strict failure on invalid percent-encoding (`%zz`), axum will not do it; `%zz` is passed literally and simply resolves to a non-existent file name, so 404 holds without extra work.
- T-1.1 can proceed: UT cases should include the strings from the tables above (`../../etc/hosts`, `%2e%2e/x`, `a\0b`, `a\b`, `/a`, empty string, `中文 筆記.md`).
